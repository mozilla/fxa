Summary
refactor(settings): replace MUI Slider with a native range input
Description
## Because

- `@material-ui/core` was pulled in for one component, the zoom `Slider` on the avatar page, and it dragged `@emotion/react` and `@emotion/styled` along with it. No source file imports `@emotion/` directly.
- A native `<input type="range">` gives the same keyboard support and screen reader announcement with no JavaScript. The dependency bought us nothing.

## This pull request

- Replaces the MUI `Slider` in `PageAvatar/index.tsx` with `<input type="range">`, same min, max, step and `aria-label`.
- Rewrites `handleSliderChange` to a normal `ChangeEvent<HTMLInputElement>` handler, which drops the `@ts-ignore` the two-argument MUI callback needed.
- Adds `zoomSliderClass`, a Tailwind class string that styles the track and thumb per vendor prefix. A range input has no cross-browser styling hook.
- Removes `@material-ui/core`, `@emotion/react`, `@emotion/styled` and the already dead `@types/material-ui` from `fxa-settings/package.json`, and refreshes `yarn.lock`.
- Adds a test that finds the control by `role="slider"` and its accessible name, then checks the zoom value updates.
