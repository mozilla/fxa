Summary
feat(settings): Add passkey HPKE key-wrapping crypto lib
Description
Because:
* Passkey PRF-derived keys need an HPKE envelope to wrap account keys
  client-side.
* The format is frozen once the first wrap exists in production — there
  is no version field — so the primitives and their sizes must be pinned
  before anything composes them.

This commit:
* Adds packages/fxa-settings/src/lib/passkey-crypto with HPKE seal/open
  and key-wrap helpers, the shared ciphersuite in suite.ts, RFC 9180 A.6
  test vectors, and tests against real Web Crypto.
* Stores skR as the raw scalar (Nsk 66) rather than a pkcs8 export, so
  every stored length is a ciphersuite constant. pkcs8's 241 bytes rest
  on Web Crypto emitting an OPTIONAL public-key field; an implementation
  that omitted it would be zero-padded into the fixed-width column and
  never open again. Serialising is left to the library, which pads short
  scalars — roughly 1 P-521 key in 512 has a leading zero byte.
* Keeps openKb taking pkR alongside the private key, so the library never
  derives it via crypto.subtle.getPublicKey, whose fallback needs an
  extractable key and fails only in browsers lacking the method.
* Guards the kB length in sealKb, since a wrong size seals to the wrong
  width and would otherwise only fail server-side.
* Adds the hpke dependency, pinned exactly, and allows it through Jest's
  transformIgnorePatterns.
