Summary
fix(settings): resolve oauth/success client id from the pathname
Description
## Because

- A hard load of `/oauth/success/:clientId` served the Backbone page. The React route group that owned the path had an empty `routes` list, and its flag is off in production.
- React mounts `PairSuccess` at `/oauth/success/:clientId/*`. On a hard load the factory built an `OAuthWebIntegration` with no `scope`, so `getPermissions()` threw errno 109 and the app rendered `OAuthDataError`.
- A bare hard load of the path also rendered the OAuth error page. `useClientInfoState()` read the client id only from the `client_id` and `service` query params, and a hard load has neither.

## This pull request

- Adds the `oauthSuccessRoutes` React route group in `server/lib/routes/react-app/index.js`, with `featureFlagOn` and `fullProdRollout` set to true.
- Reads that group in `get-oauth-success.js`, so the server stops registering the Backbone route definition.
- Removes the `oauth/success/:client_id(/)` entry from `app/scripts/lib/router.js`. The `views/ready.js` import stays, because other routes still use it.
- Sets `integration.isOAuthSuccessFlow` in `integration-factory.ts`, and returns an empty permission list for that flow in `oauth-web-integration.ts`.
- Adds `lib/oauth/success-route.ts`. `useClientInfoState()` falls back to the pathname segment through that helper, and the integration flags use the same helper.
- Adds unit tests for the flag, the empty scope, the trailing slash, and the pathname-only URL.
