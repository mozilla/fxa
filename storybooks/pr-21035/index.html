Summary
test(oauth): cover the PKCE guards on code redemption
Description
Because:

- The pairing security review turns on two claims: FxA never sees the
  code_verifier Firefox generates, and a code cannot be redeemed without it.
- Only the wrong-verifier case was covered. The /oauth/token xor that Firefox's
  redemption depends on had no tests, nor did any PKCE reject branch.

This commit:

- Adds three tests for the /oauth/token authorization_code xor, the guard a
  public client cannot sidestep with a client_secret.
- Adds five tests driving the handler's PKCE gate directly, reaching branches
  that are unreachable over HTTP.
- Adds an integration test that refuses to redeem a real code without the
  verifier, sending grant_type explicitly as Firefox does.
- Adds two tests pinning buildSyncOAuthSearch to its allowlist, so no extra
  web-channel field can reach /authorization.
- Hoists the /oauth/token payload validation helper so both describes share it.
