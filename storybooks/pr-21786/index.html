Summary
fix(settings): keep browsers that cannot approve off the pairing QR page
Description
Because:

- Firefox for Android with "Desktop site" on sends a desktop user agent, so it was routed to the authority flow and shown the pairing promo.
- It has no fxaccounts:pair_oauth_finish, so approving always failed and the phone that scanned its QR landed on the timeout screen seconds after approving.

This commit:

- Adds detectV2PairingType, which tells a phone from a desktop by its fxa_status answer, and has /pair treat a desktop user agent that answers as a phone as Firefox for Android.
- Keeps a missing pairing capability undefined in useFxAStatus, so a phone can be told from a desktop with pairing turned off.
- Sends any Firefox that opens a scanned QR to the supplicant flow or the connect hint, never the authority flow.
- Opens the scan_qr channel only with the pairing capability; other browsers go to /pair/unsupported and are reported to Sentry.
- Hides the settings "Connect a device" promo and button, and skips the ?v=2 redirect, for a browser without the capability.

Closes FXA-15081
