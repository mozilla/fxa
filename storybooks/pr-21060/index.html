Summary
perf(settings): embed the l10n asset map in index.html
Description
## Because

- Settings fetches `static-asset-manifest.json` before it can load any strings. That is a round trip before the first localized render.
- The manifest is the one unhashed object in the bundle, and it ships with `max-age=1209600`. During FXA-14361 production served a stale copy for days after the build fix landed, and every non-English locale rendered English until someone purged the cache by hand.

## This pull request

- Embeds the map of each locale's `main.ftl` to its hashed file name into Settings' `index.html`, as a `fxa-l10n-asset-map` meta tag.
- Adds `scripts/l10n-asset-map.js`. It filters the manifest down to the 88 `locales/*/main.ftl` entries the client reads, out of 678.
- Reads that meta tag in `AppLocalizationProvider` and drops the manifest fetch. An absent, empty, or malformed map stays non-fatal: the client falls back to the unhashed paths rather than throwing.
- Makes the `build-react` targets cache-correct for the manifest, with a `dependentTasksOutputFiles` input and `build-static` in the `dependsOn` of the three per-env targets. `public/static` is gitignored, so ordinary file inputs cannot see the manifest, and a cache hit could otherwise reuse a stale map.
