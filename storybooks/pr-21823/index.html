Summary
feat(passkeys): wrap kB in one AES-GCM layer, dropping HPKE
Description
Because:

- The HPKE layer's only distinct capability, re-sealing kB for a passkey
  that is not present, was already disabled by the skR AAD binding.
- What remained was a third-party curve implementation and the P-521
  platform bugs that end in an unwanted password fallback.
- No production row exists and the wrap routes are flag-off in prod, so
  this is the last point the format can change without a v2.

This commit:

- Replaces the two-layer envelope with HKDF-SHA512(prfOut, kdfSalt) and
  AES-256-GCM over kB; stored fields are kdfSalt, keyWrapIv, wrappedKb.
- Removes hpke.ts, suite.ts, the RFC 9180 vectors and the hpke dependency.
- Regenerates the golden fixture outside the module and re-pins its hash.
- Patch 203-204 drops the HPKE columns and adds kdfSalt and wrappedKb
  after clearing the table; not expand/contract, see the PR.
- Updates the auth-client, auth-server validator, repository, schema
  mirrors, Sentry filter, swagger docs and the module README.
