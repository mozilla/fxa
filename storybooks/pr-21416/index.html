Summary
fix(metrics): keep client ids out of relying_party.service in Glean
Description
Because:

* fxa-settings and older VPN clients send an OAuth RP's client id in
  `service`, and the auth-server relies on that for emails and
  verification gating, so backend Glean reported the client id in both
  relying_party fields
* The auth-server never read the metrics-context clientId, so Firefox
  sign-in events often had an empty relying_party.oauth_client_id
* The content-server form_view event named services from the stale
  OAUTH_CLIENT_IDS map

This commit:

* Report a client-id-shaped `service` only as relying_party.oauth_client_id
* Fall back to the metrics-context clientId before sniffing `service`
* Split service and client id the same way for content-server form_view
* Remove the unread oauthServer.clientIdToServiceNames config key
* Reword the fxa-settings comments on why the client id is sent as `service`

Closes FXA-13872
