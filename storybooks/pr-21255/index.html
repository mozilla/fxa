Summary
fix(settings): add fxa_pairflow entrypoint to direct pair visits
Description
## Because

- firefox.com/pair sends the user to `/pair` with only `service=sync` and `client_id`, so the visit carries no entrypoint.
- The sign-in round trip then reported no entrypoint for the pair flow, and the metrics lost the attribution.

## This pull request

- Adds the `PAIR_FLOW_ENTRYPOINT` constant (`fxa_pairflow`) in `pairing-attribution.ts`.
- Sets that entrypoint on the sign-in redirect in the `/pair` WebChannel bootstrap when the URL carries none. The redirect from firefox.com/pair lives in bedrock, outside this repo, so the client sets the value.
- Keeps the entrypoint when the visit already has one.
- Adds two tests in `Pair/Index/index.test.tsx` for the default value and for the existing value.
