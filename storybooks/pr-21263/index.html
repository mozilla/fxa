Summary
fix(settings): recover from invalid session token on signin token code
Description
## Because

- Sentry issue FXA-CONTENT-QWA logged 5.7K UnhandledRejection events on https://accounts.firefox.com/signin_token_code, mostly from Firefox iOS.
- `getTotpStatus` awaited `authClient.checkTotpTokenExists(sessionToken)` with no catch, so a stale session token turned a 401 errno 110 (`INVALID_TOKEN`) into an escaped rejection.

## This pull request

- Catches the `checkTotpTokenExists` error in `getTotpStatus` and records a `sessionTokenInvalid` flag.
- Feeds that flag to the existing OAuth native recovery effect, so those flows start flow recovery instead of reusing the dead token.
- Feeds the same flag to the existing redirect-to-root effect, so other flows go to `/`.
- Ignores every other error, because the TOTP status only picks a redirect.
- Adds a `requiresKeys` stub to `createOAuthNativeIntegration` in `mocks.tsx`, which `useOAuthKeysCheck` calls for OAuth native integrations.
