Summary
feat(settings): serve /subscriptions redirects from React
Description
## Because

- The `/subscriptions` and `/subscriptions/products/:productId` redirects still run only in the Backbone content-server app.
- These routes must move to fxa-settings before Backbone can go away.

## This pull request

- Serves `/subscriptions` and `/subscriptions/products/:productId` from a new redirect-only `SubscriptionsRedirect` page in fxa-settings. The page shows a spinner only. `App` registers both routes.
- Gates both routes with the `postVerifyOtherRoutes` React route group (`fullProdRollout: false`). Backbone still serves them until the flag is on.
- Exposes the content-server `subscriptions` config to the settings app config.
- Keeps parity with the Backbone views:
  - `allowUnauthenticatedRedirects` sends signed-out users to checkout.
  - `?signin=` forces sign-in through `/?redirect_to=`.
  - `usePaymentsNextSubscriptionManagement` picks the payments-next `subscriptions/landing` page.
  - Signed-in users get a management OAuth token in `#accessToken`.
  - It drops flow params when `metricsEnabled` is false.
- Adds unit tests for signed-in, signed-out, `?signin=`, both `usePaymentsNextSubscriptionManagement` values, and a token failure.
