Summary
chore(admin-panel): build with webpack 5 instead of rescripts
Description
## Because

- `@rescripts/cli` is unmaintained, its upstream repo is archived, and it pins the panel to `react-scripts`.
- The rescripts webpack patch reaches into create-react-app's loader array by index. It throws if that order ever changes.

## This pull request

- Moves `fxa-admin-panel` off `@rescripts/cli` and `react-scripts` onto plain webpack 5 and a direct jest config.
- Adds `config/webpack.config.js` and `config/webpackDevServer.config.js`, modeled on the `fxa-settings` pair.
- Keeps all three `.rescriptsrc.js` behaviors: the extra JS import paths (babel-loader `include`, `TsconfigPathsPlugin`, `resolve.fallback`), the dev server overlay with `runtimeErrors` off, and the jest `moduleNameMapper` built from `tsconfig.base.json`.
- Adds `jest.config.js`, modeled on `packages/fxa-react/jest.config.js`. `test-frontend` keeps its junit output path and its `#integration` filter.
- Points `build-react` at `webpack` and `test-frontend` at `jest`. Adds `start-react` for `webpack serve`, which `pm2.config.js` now calls.
- Drops the `eject` script, `react-scripts`, `@rescripts/cli` and `jest-watch-typeahead`. webpack and jest are now direct devDependencies.
- Declares the svg and css modules in `src/react-app-env.d.ts`, which no longer references `react-scripts` types.
- Deletes `.rescriptsrc.js` and the shared `packages/fxa-react/configs/rescripts.js` with its `package.json` export entry. No other package used them.
- Updates the lockfile.
