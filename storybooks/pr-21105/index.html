Summary
fix(cms): import LoggerService as a type in the CMS configuration managers
Description
## Because

- Self-hosted `fxa-auth-server` will not start. typedi throws `SyntaxError: Unexpected identifier 'Object'` while `CMSHandler` resolves the CMS managers.
- typedi never reads the NestJS `@Inject(LOGGER_PROVIDER)` decorator. It resolves each constructor parameter from `design:paramtypes` instead. Both CMS managers typed the logger as the winston `Logger`, and TypeScript serializes that to `Function`. typedi treats `Function` as constructible, so it calls `new Function(containerInstance)`. The container stringifies to `[object Object]`, which does not parse as JavaScript.
- The first attempt on this branch changed the type but imported `LoggerService` as a value. That broke the build with TS1272, because `apps/payments/next` sets `isolatedModules`.

## This pull request

- Types the injected logger as `LoggerService` in both managers. The emitted paramtype becomes `Object`, and typedi skips it as a primitive.
- Imports `LoggerService` with `import type`. `isolatedModules` requires that form for a type used in a decorated signature.
- Removes the now unused `Logger` import from `@fxa/shared/log`. `LOGGER_PROVIDER` stays.
