Summary
fix(eslint): replace ramda with native JS in ast utils
Description
## Because

- `packages/eslint-plugin-fxa` was the last package that depended on ramda, for six calls in one 126-line file.
- Those six calls have been broken since the 0.30 bump. Ramda 0.29 swapped the argument order of `propEq` and `pathEq` to put the expected value first, and `lib/util/ast.js` still passed the old order. So `isCallExpression` always returned `false` and `findReference` always returned `undefined`, which left `isDescribe`, `isTestCase`, `isHookCall`, and `isMochaFunctionCall` dead.
- None of those helpers had a test, so nothing caught it.

## This pull request

- Rewrites the six ramda calls in `lib/util/ast.js` in native JS. The rewrite does what the function names say, rather than copying the broken behaviour.
- Removes `ramda` from `packages/eslint-plugin-fxa/package.json` and updates `yarn.lock`.
- Defaults `additionalSuiteNames` to an empty array in `isDescribe`. Without it, `isMochaFunctionCall` appended a literal `undefined` to the alias list, and any callee with no name matched. That path was unreachable while `isCallExpression` was broken, so the repair is what makes it live.
- Adds `test/ast.js` for the helpers that regressed, including the case `isCallExpression` used to reject.
- Keeps every exported name and signature unchanged.
