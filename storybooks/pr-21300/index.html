Summary
refactor(content-server): remove Backbone pairing and CAD routes
Description
## Because

- `showReactApp.pairRoutes` is on in stage and prod. React serves all pairing, CAD, and CAD-via-QR routes, so nothing can reach the Backbone code for these routes.
- This change is part of FXA-6117, "Decommission Backbone".

## This pull request

- Deletes the Backbone `pair/*`, `connect_another_device`, and `post_verify/cad_qr` views, templates, mixins, models, and specs. Also deletes `sign_in_totp_code.mustache`, because FXA-14375 already landed.
- Removes the `pair/*` and `cad_qr` routes from `router.js`. `pair` and `connect_another_device` stay as React-only handlers, because Backbone views still navigate there.
- Sends `showSuccessMessage` and `type` as query params to React `connect_another_device`. React reads `type` from the query as a fallback, so the success banner stays after a hard nav.
- Removes `replaceCurrentPageWithQrCadScreen` and `replaceCurrentPageWithPairScreen` from `connect-another-device-mixin.js`. Keeps `isEligibleForPairing`, because `navigateToConnectAnotherDeviceScreen` still calls it. The ticket asked to delete it.
- Removes the `/oauth?channel_id` Backbone bypass in `add-routes.js`. Sets `pairRoutes` to `featureFlagOn: true`. `fullProdRollout` stays `true`.
- Moves `PAIRING_ROUTES` into `FRONTEND_ROUTES`. Deletes `get-frontend-pairing.js`, `getFrontEndPairingRouteDefinition`, and the `postVerifyCADViaQRRoutes` group.
- Removes the `showReactApp.pairRoutes` and `showReactApp.postVerifyCADViaQRRoutes` config values from content-server and fxa-settings.
- Changes `getSyncNavigate` in fxa-settings to always soft-nav to `/pair` with location state.
- Deletes `pairingFlowBackbone*.spec.ts`. Removes the `isPairRoutesReact` gate and the `useReact` parameter, so the React pairing specs do not skip silently. Removes the unused `SUPP_CANCEL_BACKBONE` selector and updates `tests/pairing/CLAUDE.md`.
