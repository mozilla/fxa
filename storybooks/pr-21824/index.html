Summary
feat(settings): wire the delete Sync data flow
Description
Because:

- The delete Sync data page had its UI but no behavior behind confirm.
- Signing out of the current device must land on email-first with a
  success message, like account deletion.
- A tokenserver without the delete endpoint answers a bare 404, which
  read as success and left the data in place.

This commit:

- Add Account.deleteSyncData and run delete, then sign-outs, current
  device last, with success, delete-failure and sign-out-failure alerts.
- Redirect to email-first without the query string after signing out
  this device, and show the success banner there.
- Add Glean delete_sync_data events and tag device sign-outs with
  reason sync_data_deletion; add unit tests and a Playwright spec.
- Treat a 404 without tokenserver's JSON error body as a backend
  failure; refuse sessions without password reauth with errno 237, now
  the shared passwordReauthRequired error.
- Run syncstorage-rs 0.25.2 locally with the delete endpoint enabled.

Closes #FXA-14947
