Summary
fix(settings): show blocked error on the passwordless email form
Description
## Because

- The passwordless email form navigated to the code page before any code was requested, and the code page sent the first code on mount.
- An admin blocklist hit (`REQUEST_BLOCKED`, errno 125) landed the user on the code page with no code to enter and no way forward.

## This pull request

- Sends the first passwordless code from the Index container before it navigates.
- Rethrows `REQUEST_BLOCKED` into the existing `handleEmailSubmissionError` path, so the banner shows on the email form and no navigation happens.
- Returns false for any other send failure, so the flow navigates as before and the code page sends again and reports the error.
- Passes `codeSent: true` in location state on success, so the code page skips its mount send and the flow makes one `send_code` request.
- Moves `GleanMetrics.emailFirst.submitSuccess` after `handleSuccessNavigation`, so a blocked send records `submitFail` only.
