Summary
fix(payments-ui): keep subscription mode for below-minimum upgrades
Description
Because:
- An upgrade prorated below the Stripe minimum charge leaves a pending SetupIntent on the subscription.
- Elements in setup mode creates a confirmation token Stripe refuses for that SetupIntent, which failed the cart.

This commit:
- Keeps Elements in subscription mode and passes an amount of 0 when below the minimum charge.
- Adds a StripeWrapper test for the mode and amount passed to Elements.
- Adds a payWithStripe test for an upgrade whose paid invoice comes with a pending SetupIntent.

Closes PAY-3767
