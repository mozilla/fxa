Summary
feat(oauth): deauthorize account authorizations on disconnect
Description
Because:

- Withdrawing an authorization meant deleting the row, which also
  discards the ToS record Product needs kept until account deletion.
- The token-exchange gate could not tell "has ever authorized" apart
  from "is authorized now"; both answers came from row presence.
- Nothing retired an authorization when a client was disconnected, so a
  withdrawn grant kept working.

This commit:

- Adds a nullable deauthorizedAt column, fxa_oauth 039 to 040, appended
  and unindexed so the ALTER is INSTANT on the live table. The
  accountAuthorizations_v2 shadow table is left unfiltered: it is being
  removed.
- Filters the sign-in and token-exchange reads on deauthorizedAt IS
  NULL, leaving the first-authorization checks unfiltered by design.
  Re-authorizing through /authorization clears it. prompt=none and token
  exchange write nothing, as before: the user sees no ToS.
- Adds deauthorizeAccountAuthorizations, guarded on the
  lastAuthorizedTosAt the caller read so a racing re-auth survives. The
  upsert advances that timestamp on every completion, so the guard holds
  for a re-auth in the same millisecond or on a slow clock.
- On Connected Services and device disconnect, judges the rows the
  disconnected client could have been sustaining: its own, plus any
  whose service allowlists it. A row survives while a covering refresh
  token is held by its own client or an allowlisted one, so a browser
  that reached VPN via token exchange (which writes no row) keeps the
  consent alive. Tokens lost any other way (password reset, RFC 7009
  destroy, pruning) never deauthorize a row. The pass runs even when the
  disconnect errors, since the token delete commits before its Redis
  cleanup. The allowlist default now matches the prod override.
- Exempts Firefox Desktop, which holds no refresh token until
  bz2053654 and signs out by session token. A session carries no client
  or scope identity, so we cannot tell which services it authorized;
  its rows stay active.

Closes FXA-14015
