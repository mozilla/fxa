fix(settings): handle invalid session token on signin token code
Description
## Because

- Sentry recorded 5.7K events on https://accounts.firefox.com/signin_token_code, mostly from Firefox iOS.
- `getTotpStatus` did not catch errors from `checkTotpTokenExists`. A 401 with errno 110 (`INVALID_TOKEN`) became an unhandled rejection.

## This pull request

- Wraps the `checkTotpTokenExists` call in try/catch, and adds `integration` and `navigateWithQuery` to the effect dependencies.
- Sends the user to `/` on errno 110, the same route the missing signin state effect uses.
- Keeps OAuth native integrations on the page, which matches the missing state branch.
- Ignores every other error, because the TOTP status only picks a redirect. The code page still works without it.
- Adds three container tests, and gives the auth client mock a stable `checkTotpTokenExists` that each test controls.
