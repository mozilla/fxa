Summary
fix(metrics): stop stashing clobbering a client-supplied service
Description
Because:
 - stash() assigns metadata.service from the request unconditionally, so a
   service already present on the metrics context is overwritten with undefined
   when the request carries none
 - /session/reauth sends no top-level service, and sendSigninNotifications
   stashes before emitting the login event, so login.complete for a Sync passkey
   sign-in lands with an empty relying party while the ceremony reports sync
 - That splits one login across two relying-party buckets in reporting

This commit:
 - Falls back to the existing metrics context service when the request supplies
   none, leaving the request value ahead of it when present
 - Covers both orderings in the stash tests

Closes #FXA-14302
