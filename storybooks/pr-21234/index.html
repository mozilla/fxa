Summary
feat(passkey): Add the passkey verification ceremony
Description
Because:

* A signed-in user with a passkey had no way to authorize an MFA action
  without signing in again; only an emailed OTP could mint a scoped token.
* A token minted at sign-in expires during password entry, and the client
  needs a fresh one without a second sign-in.
* The uid-bound assertion challenge is the general step-up ceremony, not the
  PRF key-wrapping one it was named for.

This commit:

* Renames the 'upgrade' challenge type to 'verification', requires a scope on
  it, and stores an optional pinned credentialId.
* Adds POST /passkey/verification/{start,finish}, session-authenticated and
  returning an mfaToken bound to the session and asserting credential.
* Adds PasskeyService.generateVerificationChallenge and
  verifyVerificationResponse, sharing assertion verification with sign-in.
* Adds passkey.verification_{started,success} Glean events,
  account.passkey.verification_{success,failure} events, and fxa patch 199-200.
* Adds beginPasskeyVerification and completePasskeyVerification to
  fxa-auth-client.
