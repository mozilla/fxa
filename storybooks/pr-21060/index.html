Summary
fix(settings): stop the dev server compressing index.html
Description
## Because

- The functional suite went red on this branch after the manifest embedding landed. Every spec timed out on its first navigation, which means Settings never booted.
- The `fxa-l10n-asset-map` meta tag adds 6,563 characters to `index.html`. That takes the file from 1.4 KB to roughly 8 KB, past the 4 KB gzip threshold on the Settings dev server.
- Once the dev server compressed the HTML, `modifyProxyRes` in `beta-settings.js` copied `content-encoding: br` onto the response, then ran `body.toString()` and the token replacement over the compressed bytes. The browser got a body that no longer matched the header, `__SERVER_CONFIG__` never resolved, and nothing rendered.

## This pull request

- Exempts `text/html` from the compression middleware in `webpackDevServer.config.js`, so the dev server serves `index.html` uncompressed.
- Keeps the 4 KB threshold and the default compressible-type check for everything else, so JS and CSS still compress.
- Leaves the asset map, `AppLocalizationProvider`, and the nx cache inputs alone.
