Summary
chore(metrics): stop sending the legacy accounts-events Glean ping
Description
## Because

- The `events` ping with the Glean `event` metric type replaced `accounts-events`, and every known consumer uses it.
- Each frontend event sent two pings. Each backend event wrote two log entries.
- `login_backup_choice_submit` and `account_pref_two_step_auth_qr_view` received a `reason` from the caller but did not record it. Only the removed ping carried it.

## This pull request

- Removes the `accounts-events` ping and the `event.*` string metrics from the Glean YAML files.
- Removes the ping submit and the legacy record calls from fxa-settings, content-server and auth-server. Regenerates the Glean modules.
- Keeps `fxa-ui-pings.yaml`, `fxa-backend-pings.yaml` and the backend compat YAML as schema-only stubs. probe-scraper still fetches them by path.
- Passes the caller's `reason` to `login.backupChoiceSubmit` and `accountPref.twoStepAuthQrView` in fxa-settings.
- Updates the Glean unit specs and `packages/functional-tests/lib/glean.ts` to read the `events` ping.
- Drops `accounts-events` from `pairingChannelHash` `sendInPings`.
- Removes the legacy record assertions from the three `step_up_auth_*` auth specs.
