Summary
fix(auth): sustain the bandaid's canonical row through disconnects
Description
Because:
- Rows written for clients in serviceForClient carry a canonical scope
  their tokens don't hold, so no remaining token ever covered them.
- The first disconnect of any client on the service's allowlist
  deauthorized the row while the app was still signed in, and the next
  token exchange for that scope failed with errno 112.

This commit:
- Adds impliedScopeForClient to authorizationRowsToDeauthorize: a token
  from a mapped client counts as covering that service's canonical scope.
- Wires it from deauthorizeOnDisconnect via the same config map.
- Covers the rule, the wiring, and the caller mocks.
