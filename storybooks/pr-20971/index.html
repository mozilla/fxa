Summary
test(fxa-shared): Make experiments/base tests deterministic
Description
Because:

* The hash and luckyNumber tests hashed 1000 Math.random() values and
  asserted every result was unique. The hash is 32 bits, so by the
  birthday paradox a collision occurred roughly 1% of the time.
* Every other statistical assertion in the file was fed Math.random()
  or crypto.randomUUID() too, so they can fail on a run where nothing
  changed.
* The shared experiment instance is mutated by the deprecated test,
  and hash() mixes in this.name, so the hashing tests were order
  dependent.

This commit:

* Replaces the random input with a fixed key set, derived once with
  sha256 so the sample keeps the entropy of a real uid and shares no
  structure with the md5 under test.
* Replaces the uniqueness assertions with the behaviour actually under
  test: output range, stability for a given key, and spread across the
  output range.
* Asserts hash() returns an integer and luckyNumber() a non-NaN number,
  which the range checks alone did not cover.
* Pins golden hash values, since a change there re-buckets every user.
* Builds a fresh experiment per test.

Fixes FXA-14281
