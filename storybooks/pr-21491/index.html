Summary
fix(auth): lock passkey ceremonies to a fixed mfa:passkey:wraps scope
Description
Because:

- The passkey start routes accepted any `config.mfa.actions` scope, so a
  passkey assertion could mint `mfa:2fa`, `mfa:email`, `mfa:password` or
  `mfa:recovery_key` and skip the email OTP step-up (FXA-14740).
- The only thing a passkey ceremony needs to authorize is the wrap routes.

This commit:

- Drops the client-provided `scope` from `/passkey/authentication/start`
  and `/passkey/verification/start`; both commit the challenge to a
  hard-coded `passkey:wraps` action.
- Signs `mfa:passkey:wraps` at both `/finish` routes; `authentication/finish`
  always returns `mfaToken`.
- Requires `mfa:passkey:wraps` on the `/passkey/wraps` routes, so the email
  OTP can no longer open them.
- Removes the `scope` option from the auth-client and settings callers.
- Rewrites the swagger notes for the fixed scope.

Fixes FXA-14740
