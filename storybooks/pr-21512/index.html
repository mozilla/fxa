Summary
fix(settings): wait for a fresh fxa_status after sign-in reaches /pair
Description
Because:

* Sign-in moves to /pair in the router, so useFxAStatus kept the
  signed-out answer from the sign-in page and reported it as current.
* Firefox answers /pair's own fxa_status only after oauth_login's
  token exchange, which can outlast its 1 s of retries.
* /pair then bounced a just-signed-in Sync user to cached sign-in, or
  showed the v1 screen on a v2-capable Firefox.

This commit:

* Reports fxaStatusState as 'pending' during render when isPairing
  changes, before pages' effects can act on the old answer.
* Stops the effect re-running, and re-asking, once engines arrive.
* Adds hook tests for both.

Closes #FXA-14762
