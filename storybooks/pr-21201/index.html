refactor(auth-server): remove unused email from recoveryKey/exists
Description
## Because

- `POST /recoveryKey/exists` has required auth since FXA-9398. The handler reads the uid from `request.auth.credentials`.
- The `email` field in the payload is dead weight. The route validator, the `fxa-auth-client` signature, and the callers all still carried it.

## This pull request

- Drops `email` from the payload validator in `recovery-key.js`. The payload stays optional and nullable.
- Narrows `recoveryKeyExists` to `(sessionToken, headers?)` and removes the unauthenticated fallback branch.
- Updates the callers in `Account.ts`, `hooks.ts`, and the Signin container, plus the assertions in `container.test.tsx`.
- Deletes `checkRecoveryKeyExistsByEmail()` from the content-server account model. It had no callers.
- Deletes the `getRecoveryKeyExistsWithEmail` test helper from `test/client/api.js`. It had no callers.

## Issue that this pull request solves

Closes: FXA-10441
