Summary
fix(free-access-program): delay RP notifications past memory cache TTL
Description
Because:

- reconcile clears only its own process's memory cache, so an RP re-fetching
  right after a notification can hit an instance still serving the old
  projection for up to memCacheTTL

This commit:

- queues changed emails in a Firestore `state/pending` subcollection with
  notBefore = memCacheTTL + 60s
- sends due notifications from reconcile (at most 500 per run, oldest first)
- deletes each sent doc with an update-time precondition so re-queues survive
- adds memoryCacheTtlSeconds() as the single source for the delay and cache
- deletes malformed pending docs and treats superseded deletes as expected
