Summary
fix(settings): destroy the browser session token on sign-out
Description
## Because

- After a forced web sign-in (`prompt=login`) replaces the stored session token, Settings sign-out destroyed only the stored token.
- Sign-out then sent `fxaccounts:logout`, and Firefox signed out locally only. The browser's own session stayed valid on the server.

## This pull request

- Updates `DropDownAvatarMenu/index.tsx`. In Firefox, sign-out asks `fxa_status` for the browser's signed-in user.
- If that user has the same uid and a different session token, the menu destroys that token with `authClient.sessionDestroy` before `fxaccounts:logout`.
- The menu ignores errors from that destroy call, so the local sign-out and `fxaccounts:logout` still run.
- Adds unit tests in `DropDownAvatarMenu/index.test.tsx`: token mismatch, other account, no reply, no token, same token, non-Firefox, and destroy failure.
- Adds a functional test in `fxaStatus.spec.ts`: sign-out destroys the browser session after a web sign-in replaced the stored token.
- What this round fixed (red CI on PR #21377):
  - `HeaderLockup` and `SettingsLayout` tests now pass `mockAppContext()`, because `DropDownAvatarMenu` reads `authClient`.
  - The functional test signs in to Sync with `context=fx_desktop_v3` instead of `/pair`. The `/pair` flow never reached the "Not now" pair link, so the test timed out.
