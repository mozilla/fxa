Summary
feat(settings): route camera-scanned pairing links by mobile browser
Description
Because:
- An iOS QR scan from the system camera opens /pair in the default
  browser, and every browser there dead-ended on /pair/unsupported.
- Legacy pairing let the user say whether they already had Firefox;
  v2 lost that choice.
- Safari alerts on an unhandled firefox:// link, so the inferred store
  fallback cannot be trusted there.

This commit:
- Sends mobile Firefox that cannot take v2 to /pair/supplicant/connect_hint,
  and every other iOS browser to the download screen.
- Deep-links the connect hint until iOS is in the v2 rollout, then the pair URL.
- Adds isIosSafari; Safari gets Download Firefox plus I already have Firefox
  in place of the single Continue in Firefox CTA.
- Restyles the download screen to the Figma design, with new Fluent ids.
- Updates the unit and Playwright coverage and the stale rollout comments.

Closes #FXA-14595
