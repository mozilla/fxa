Summary
refactor(auth-server): remove unused email from recoveryKey/exists
Description
## Because

- `POST /recoveryKey/exists` has required auth since FXA-9398. The handler reads the uid from `request.auth.credentials`.
- The `email` in the payload is therefore dead weight, but the route validator, the `fxa-auth-client` signature, and the call sites all still carry it.
- Clients from older releases still post `email`. The route must keep accepting that body.

## This pull request

- Drops `email` from the payload validator in `recovery-key.js`, and pins `stripUnknown` on the route, so a legacy `{ email }` payload is accepted and the field is ignored.
- Narrows `recoveryKeyExists` to `(sessionToken, headers?)` and removes the unauthenticated branch.
- Updates the call sites in `Account.ts`, `hooks.ts`, and the Signin container, plus the assertions in `container.test.tsx`.
- Deletes two helpers that had no callers: `checkRecoveryKeyExistsByEmail()` in the content-server account model, and `getRecoveryKeyExistsWithEmail` in `test/client/api.js`.
- Adds schema tests in `recovery-key.spec.ts` for the omitted, null, empty, and `{ email }` payloads.

## Issue that this pull request solves

Closes: FXA-10441
