Summary
test(settings): cover per-run interval ownership in bounce polling
Description
## Because

- The signup confirmation page polled `account/email_bounce_status` every 5 seconds for as long as the page stayed open. There was no cap.
- The `catch` block only logged, so the 429s that stage returns did not stop it. The page kept calling an endpoint that was already rate-limiting it.

## This pull request

- Stops polling 10 minutes after the effect starts, measured by wall-clock time rather than a tick count, because a backgrounded tab throttles timers.
- Stops polling as soon as a request fails with a 4xx or a 5xx. An error with no `code`, such as a network failure, keeps polling.
- Stops polling once a hard bounce is found.
- Clears the interval on all of those paths. Each effect run holds its own interval id, so a check left in flight by a previous run cannot stop the current one. That made `pollIntervalRef` write-only, so it is gone.
- Adds a test that leaves a check in flight, re-runs the effect with a new auth client, then fails the stale check, and asserts the new run keeps polling and the old run stays stopped.
