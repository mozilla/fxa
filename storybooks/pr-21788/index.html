Summary
fix(settings): resume a pairing socket that goes silent without closing
Description
Because:

- A page cannot see WebSocket pings, so a connection that dies with no close event was never resumed and the pairing failed when the channel expired.

This commit:

- Asks the channel server for keepalive messages and keeps them from the channel.
- Tries a resume after 15 s without traffic on a visible page.
- Leaves the silent socket open until the resume succeeds, and keeps it if it speaks first.
