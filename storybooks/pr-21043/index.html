Summary
fix(settings): order l10n bundling before static asset hashing
Description
Because:
- The nx upgrade in v1.342.0 replaced a sequential build chain with sibling
  dependsOn entries, letting hash-static race l10n-bundle.
- Prod shipped a manifest with no main.ftl keys, so the settings app fetched
  no FTL at all and every locale fell back to English.
- The failure was silent in both the build and the browser.

This commit:
- Adds build-l10n to build-static's dependsOn.
- Fails hash-static when a locale has no main.ftl in the manifest.
- Reports whole-bundle l10n load failures to Sentry.
- Buffers those reports until metrics are enabled, since they happen before
  App can mount.
