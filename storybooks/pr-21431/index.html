Summary
fix(settings): ask 2FA accounts for their code before approving a v2 pairing
Description
Because:
- The v2 pairing flow approved a sign-in from the desktop without asking a
  2FA account for its TOTP code, unlike v1.

This commit:
- Adds /pair/authority/totp, reusing the v1 AuthTotp page, and sends 2FA accounts there before the approval screen.
- Re-prompts for the code if the approval screen has been open longer than four minutes.
- Shares the TOTP-required check between v1 AuthAllow and the v2 container.
- Rejects a web channel command promptly when Firefox replies with an error for it.
- Registers the route in both content-server lists and adds a v2 functional test.

Fixes FXA-14643
