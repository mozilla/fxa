Summary
refactor(auth): remove customs server and legacy customs client
Description
## Because

- The `@fxa/accounts/rate-limit` library now makes every rate-limit decision, so the customs server gets no traffic.
- The `default` rule in `config/rate-limit-rules.txt` already catches every action, so the legacy HTTP path is unreachable in production.

## This pull request

- Deletes `packages/fxa-customs-server`.
- Removes the legacy HTTP client from `lib/customs.js`: `this.url`, `makeRequest`, the `/check`, `/checkAuthenticated` and `/checkIpOnly` fetches, `sanitizePayload`, `optionallyReportStatsD` and `handleCustomsResult`.
- Keeps the `check`, `checkAuthenticated` and `checkIpOnly` names. They now run the v2 `rateLimit` path only.
- Drops `customsUrl` and `customsClient` from `config/index.ts`, `config/dev.json`, `bin/key_server.js` and four test helpers.
- Drops the legacy HTTP tests from `lib/customs.spec.ts`, rewrites the README rate-limiting section, and refreshes `yarn.lock`.
