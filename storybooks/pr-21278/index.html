Summary
chore(deps): remove bluebird from profile-server and geodb
Description
## Because

- Bluebird is an extra dependency. Native promises cover everything the two packages used it for.
- The Bluebird-only helpers (`P.using`, `.spread`, `.done`, `P.each`, `.map`) hid where the code waits and where it does not.

## This pull request

- Removes the `bluebird` dependency from `fxa-profile-server` and `fxa-geodb`, and deletes `lib/promise.js`.
- Replaces `P.using` and its disposer in the MySQL store with a small `_withConnection` helper. The helper releases the connection in a `finally` block, so a failed query still returns the connection to the pool.
- Replaces `P.promisify` with `util.promisify`, and `.spread`, `.done`, `P.each` and `.map` with `Promise.all`, `.then` and `async`/`await`.
- Adds a `.catch` to the detached `profileCache.drop` call in `lib/events.js`. Nothing waits on that call, so it must log its own failure.
- Adds tests for two behaviors that the conversion introduces: the connection release in `_withConnection`, and the detached `profileCache.drop` rejection path in `lib/events.js`.
