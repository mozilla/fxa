Summary
feat(settings): serve force password change page from React
Description
## Because

- Only the Backbone app serves the force password change page. The `postVerifyOtherRoutes` React group has no routes yet.
- FxA sends a user to this page when the account must get a new password before sign-in can complete.

## This pull request

- Adds a React `ForcePasswordChange` page to fxa-settings at `/post_verify/password/force_password_change`, with a container, page, interfaces, mocks, `en.ftl`, stories, and tests.
- Adds the route to the `postVerifyOtherRoutes` flag group (`fullProdRollout: false`) in the content-server `react-app/index.js`. `router.js` now uses `createReactOrBackboneViewHandler` for the route and forwards the search params.
- Sends signed-out users to `/`. On submit, the container calls `authClient.passwordChange` with `keys: integration.wantsKeys()` and stores the new session.
- Sends `firefox.passwordChanged`, as the Backbone notifier does for `CHANGE_PASSWORD`. Then it calls `handleNavigation` as a verified sign-in, in place of the broker `afterCompleteSignInWithCode`.
- Adds a `force-password-change` form type to `FormPasswordWithInlineCriteria`, with an "Old password" field and a "Change password" button. `PasswordStrengthInline` treats this type like reset.
- Ports the legacy flow events `force-password-change` view, engage, and submit. This page has no Glean events.
