Summary
feat(settings): resume the pairing channel when its socket drops
Description
Because:

- A backgrounded mobile browser can drop the pairing WebSocket, which fails pairing for users who leave Firefox to read a TOTP code.

This commit:

- Adds ResumableWebSocket, which reconnects with the channel server's resume token and sends queued data after it resumes.
- Uses it for both the supplicant open() and authority create() channels through withResumableWebSocket().
- Sends the token as the `resume.<token>` subprotocol and uses the rotated token on each later drop.
- Stops at once on its own close() or on close code 4000, which the channel server sends when it ends the channel.
- Keeps plain WebSocket behaviour when the channel server sends no token.

Closes #FXA-14663
