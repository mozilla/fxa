fix(settings): redeem the signin confirmation code once
Description
Because:
- The effect that redeems the code has no dependency array, so it re-runs on every render.
- The code is single-use, so a second attempt fails with INVALID_VERIFICATION_CODE and shows the link as expired.
- Each extra attempt also spends a customs check and emits another email.verify_code.clicked event.

This commit:
- Gates the redemption on a ref so a re-render cannot start a second attempt.
- Covers the guard for both the double-mount and the error-path re-render.
- Shares the auth-client mock across the container tests so call counts are assertable.
