Summary
feat(settings): gate pairing on the browser holding the Sync key
Description
Because:
- A Firefox session without the Sync key (VPN/Relay/Smart Window cached
  sign-in, third-party auth) passed every "signed in" check, so pairing
  started and failed in the browser with "No keyFetchToken"
- Firefox now reports `signedInUser.hasSyncKey` in `fxa_status`
  (Bug 2080354); `undefined` from older Firefox keeps today's path
- The Sync sign-in /pair fell back to landed on email-first, which showed
  a cached sign-in step first and could not tell a passwordless account
  from one that has a password

This commit:
- Adds `canPairFromBrowser` for /pair and /connect_another_device;
  /pair sends a key-less browser session to /post_verify/set_password,
  which creates a password or hands an account that has one to /signin
- Makes set_password verify the session first (code or TOTP page, then
  back), since Firefox deep-links there and /password/create needs a
  verified session
- Labels the /signin submit "Start syncing" when sent from set_password
- Hides the Connect-a-device promo and Connected Services button in
  Settings when the browser reports no key
- Drops the unused `capabilities.hasSyncKeys` type and adds Playwright
  password → /pair and password → 2FA → /pair flow tests
