Summary
fix(payments): read stripe inside transaction
Description
Because:

* Concurrent subscription webhooks could leave a stale "incomplete"
  subscription in Firestore after Stripe had moved it to "active"
* fetchAndInsertCustomer read Stripe outside its transaction and gated
  writes on a per-second event timestamp that other writers erased

This commit:

* Locks customer and subscription docs before re-reading Stripe in the transaction
* Removes the stripeEventCreatedTime check on customer and subscription docs
* Drops the unused eventTime and ignoreErrors params of fetchAndInsertCustomer
* Adds unit tests for fetchAndInsertCustomer

Closes #PAY-3937
