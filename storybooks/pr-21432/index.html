Summary
fix(settings): send a signed-out desktop off the v2 pairing QR page
Description
Because:

- The v2 scan_qr page never read the browser's sign-in status, so after
  a sync sign-out a reload or the timeout page's retry still minted a
  channel and showed a QR.
- A phone that scanned it was approved by a desktop with no account, so
  its flow fell back to login.

This commit:

- Passes the already-fetched fxa_status result into the ScanQR container.
- Waits for the status and only opens a channel for a verified signed-in
  user, otherwise hard-navigates to /pair, which owns the signed-out desktop.
- Adds container tests for pending, signed-out, unverified, disconnected
  and unanswered browsers.

Fixes FXA-14657
