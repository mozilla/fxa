Summary
fix(settings): show canceled screen on desktop when mobile cancels pairing
Description
Because:

* Cancelling on mobile only closed the channel, and the desktop cannot
  tell a closed channel from an expired one, so it showed "Looks like we
  timed out" for a pairing the mobile user deliberately stopped.
* The desktop already tells mobile when it cancels; the reverse notice
  was missing.

This commit:

* Adds PairingSupplicantIntegration.cancel(), which sends pair:supp:cancel
  before closing the channel.
* Handles pair:supp:cancel on the authority and exposes canceledBySupplicant.
* Routes the mobile Cancel buttons through cancel() instead of destroy().
* Passes reason 'canceled' or 'timeout' from the desktop Failed handlers.
* Covers the notice, the flag ordering, and both container reasons.

Closes #FXA-14608
