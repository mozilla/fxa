Summary
chore(deps): upgrade commander to 13.1 and migrate CLI scripts
Description
## Because

- FxA used commander 2.18.0 in fxa-auth-server and 9.3.0 in fxa-profile-server, both old.
- fxa-admin-server imported commander but had no direct dependency on it. It used the hoisted 2.18 copy, which this upgrade removes.
- Since commander 7, options live on `program.opts()`, not on the command object. A read like `program.delay` gives `undefined` after the upgrade, and the script silently uses its fallback.

## This pull request

- Bumps commander to `^13.1.0` in fxa-auth-server and fxa-profile-server.
- Adds commander `^13.1.0` as a direct dependency of fxa-admin-server.
- Changes 38 scripts to named imports (`{ program }` or `new Command()`).
- Reads all options through `opts()`. Without this, bulk-mailer would ignore `--delay` and `--batchsize`, and clean-up-old-ci-stripe-customers would ignore `--emailPattern`.
- Changes numeric option defaults to strings, because the commander 13 typings reject numbers. Every consumer already calls `parseInt` or coerces the value. Values from the CLI were always strings.
- Writes exponent literals such as `100e3` as plain digits, because `parseInt('100e3')` is `100`.
- Adds `.allowExcessArguments()` to delete-unverified-accounts.ts and clean-up-partial-account-customer.ts. Their `--limit` flag takes no value, and v13 stops on the stray value. This keeps the 2.x behaviour.
- Changes `<events...>` to `<events>` in google-events-cli.js. In v13 the variadic form gives an array, and `.split(',')` would throw.
- yarn.lock only removes the 2.18.0 and 9.3.0 entries.
