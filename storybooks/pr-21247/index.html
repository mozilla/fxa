Summary
feat(content-server,settings): serve React for oauth/success route
Description
## Because

- A hard load of `/oauth/success/:clientId` served the Backbone page. The React route group that owned the path had an empty `routes` list, and its flag is off in production.
- React already mounts `PairSuccess` at `/oauth/success/:clientId/*`. On a hard load the factory built an `OAuthWebIntegration` with no `scope`, so `getPermissions()` threw errno 109 and the app rendered `OAuthDataError`.

## This pull request

- Adds the `oauthSuccessRoutes` React route group in `server/lib/routes/react-app/index.js`. It takes its routes from `OAUTH_SUCCESS_ROUTES`, with `featureFlagOn` and `fullProdRollout` set to true.
- Reads the new group in `get-oauth-success.js`, so the server stops registering the Backbone route definition.
- Removes the `oauth/success/:client_id(/)` entry from `app/scripts/lib/router.js`. The `views/ready.js` import stays, because six other entries use it.
- Sets `integration.isOAuthSuccessFlow` in `integration-factory.ts`, and returns an empty permission list for that flow in `oauth-web-integration.ts`.
- Matches the client id segment in `isOAuthSuccessFlow()`, so a trailing slash still resolves. Backbone accepted the trailing slash.
- Adds unit tests for the flag, the empty scope, and the trailing slash.
