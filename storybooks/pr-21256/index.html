Summary
fix(pairing): keep a reload from landing on the timeout screen
Description
Because:
- Firefox stops the document's network activity before it unloads, so
  the pairing socket closes while page script still runs.
- The integrations treated that close as a failure and pushed the
  timeout route in the dying page, which the reload sometimes committed.

This commit:
- Ignores channel closes and errors that arrive after beforeunload or
  pagehide; a pageshow makes the page live again.
- Does not fail the flow when the unload cuts short a channel create or
  open still in flight, on both the authority and the supplicant.
- Adds unit tests for the unload handling.

Closes #FXA-14485
