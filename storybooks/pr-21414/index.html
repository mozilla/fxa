Summary
feat(oauth): allow profile:avatar for untrusted clients
Description
## Because

- An untrusted relying party (RP) that asked for `profile:avatar` did not get it.
- The auth server rejected the scope with errno 114. Settings dropped it without an error.

## This pull request

- Adds `profile:avatar` to `UNTRUSTED_CLIENT_ALLOWED_SCOPES` in `grant.js`.
- Adds `profile:avatar` to `OAUTH_UNTRUSTED_ALLOWED_PERMISSIONS` in the Settings `constants.ts`. This list is where Settings dropped the scope.
- Adds `profile:avatar` to `DISPLAYABLE_PERMISSIONS`, after email and display name.
- Adds an "Account picture" row to the Permissions consent screen (Fluent id `permissions-label-avatar`). The row shows the label only.
- Adds tests for the server allow-list, the Settings scope filter, the row order, and the new row.
