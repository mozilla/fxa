Summary
chore(deps): upgrade commander to 13.1 and migrate CLI scripts
Description
## Because

- fxa-auth-server pinned commander 2.18, which is several major versions behind.
- Commander 7 and later no longer store options on the command object. Old `program.<opt>` reads return `undefined`, so scripts quietly fall back to defaults.

## This pull request

- Upgrades commander to `^13.1.0` in fxa-auth-server and fxa-profile-server, and adds it as a direct dependency of fxa-admin-server.
- Migrates the CLI scripts to the named `Command`/`program` import and reads options through `program.opts()`.
- Makes `--limit` take a value (`--limit <number>`) in `clean-up-partial-account-customer.ts` and `delete-unverified-accounts.ts`. As a boolean flag, `--limit 10` parsed to NaN, so no limit applied and a non-dry run enqueued every matching account. The limit guard is now `!(limit > 0)` so it rejects NaN, `.allowExcessArguments()` is gone so commander still rejects stray arguments, and `options.uid.size` is now `options.uid.length` because `uid` is an array.
