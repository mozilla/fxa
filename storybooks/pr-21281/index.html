Summary
refactor(auth): remove preVerified option from account creation
Description
## Because

- `preVerified` was a test-only option on `POST /account/create`. It made the server create an already verified account and an already verified session.
- The option never worked in production. Tests that used it took a path that no real user takes, so they did not cover the signup flow they claimed to cover.

## This pull request

- Removes the `preVerified` form field and its Joi validator from `account.ts`. New accounts are always created unverified, and the session token always gets `tokenVerificationId = emailCode`.
- Deletes the three branches that this made dead: the `verified` attached-services notification in create, the early return in `sendVerifyCode`, and the two `if (tokenVerificationId)` guards.
- Removes `preVerified` from `SignUpOptions` in `fxa-auth-client`.
- Moves `createAccount` into `BaseTarget`. It signs up, then confirms the account with the code from the signup email. This is what `remote.ts` already did for production. Ten specs stop passing `preVerified`. Specs that want an unverified account now pass `verified: false`.
- Adds an assertion in `account.spec.ts` that holds the new rule: create stores `emailVerified: false`, and the session token gets `tokenVerificationId === emailCode`.
- Cleans up the last references in `test/client/api.js`, `test/load/loadtests.py`, two remote specs, `fxa-client.js` and `constants.ts`.
