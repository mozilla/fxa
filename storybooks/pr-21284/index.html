Summary
fix(settings): harden the passkey wrap opt-in
Description
Because:
- Wrap material could outlive the sign-in on unverified, non-OAuth and
  other-account exits.
- The kB stash threw from inside its own catch when no ceremony was pending.
- The opt-in's Enable button could re-enter while its buffers were being
  zeroed.

This commit:
- Gate the opt-in on a uid match, OAuth Sync and a verified session so the
  existing clear covers every other exit.
- Move the kB stash onto SensitiveDataClient as a method that cannot throw.
- Add a synchronous re-entry guard to the opt-in Enable button.
- Narrow caught store errors to AuthUiError; share the AAD uid derivation.
- Add a useMounted hook and use it in the opt-in container.
