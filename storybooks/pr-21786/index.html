Summary
fix(settings): keep browsers that cannot approve off the pairing QR page
Description
Because:

- Firefox for Android with "Desktop site" on sends a desktop user agent, so it was routed to the authority flow and shown the pairing promo.
- It has no fxaccounts:pair_oauth_finish, so approving always failed and the phone that scanned its QR landed on the timeout screen seconds after approving.

This commit:

- Opens the scan_qr channel only when fxa_status reports the pairing capability; other browsers go to /pair/unsupported.
- Records that capability on the Firefox channel from each fxa_status reply.
- Hides the settings "Connect a device" promo and button for a browser without it.

Closes FXA-15081
