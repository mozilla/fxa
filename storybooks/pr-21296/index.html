Summary
feat(settings): serve force password change page from React
Description
## Because

- Only the Backbone app serves the force password change page. FxA sends a user there when the account must get a new password before sign-in can complete.
- The `postVerifyOtherRoutes` React group has no routes yet.

## This pull request

- Adds a React `ForcePasswordChange` page at `/post_verify/password/force_password_change`, with a container, stories, and tests. The container calls `authClient.passwordChange`, stores the new session, sends `firefox.passwordChanged`, and then calls `handleNavigation` as a verified sign-in.
- Adds the route to the `postVerifyOtherRoutes` flag group (`fullProdRollout: false`). `router.js` uses `createReactOrBackboneViewHandler` for the route and forwards the search params.
- Adds a `force-password-change` form type to `FormPasswordWithInlineCriteria`, with an "Old password" field and a "Change password" button. `PasswordStrengthInline` treats this type like reset.
- Ports the legacy `force-password-change` flow events (view, engage, submit). The page has no Glean events.
- Fixes the CI functional test failures:
  - The page now uses the Backbone element ids that `postVerify.ts` looks for, through a new optional `id` prop on `InputText` and `InputPassword`. No functional test changed.
  - `handleNavigation` now navigates in-app, with query params, for `CHANGE_PASSWORD`. The old hard navigation got a 301 to a trailing-slash URL, and that URL returned 404.
  - The container reads `verified` from the `passwordChange` response. `/password/change/finish` returns `verified`, not `sessionVerified`, so users went back to `/signin_token_code` after the change.
