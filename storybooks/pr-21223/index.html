Summary
feat(settings): let the passkey opt-in retry recoverable failures
Description
Because:
  * A dismissed prompt or a rate limit left the sealed envelope unused
    but sent the user to Settings with no way to act on either.
  * Sealing read key material the page could zero mid-flight, storing a
    wrap that opens to zeroes and passes its own round-trip check.
  * A server refusal lost its errno on the step-up path, and the
    unexpected ones produced no telemetry at all.

This commit:
  * Exports retryPasskeyWrapStore to resubmit an already-sealed envelope.
  * Holds the offer behind a banner when a prompt or a limit stops it.
  * Seals over copies, zeroing the originals once an envelope exists.
  * Passes an errno through from the verification calls, and reports
    unexpected authenticator errors to Sentry.
  * Adopts the approved copy, one message for every terminal failure.
