Summary
fix(admin): run disable matching accounts as a background job
Description
Because:
* Scanning every account inside the request outlasts the 30s gateway
  timeout, so the blocklist pages got a 504 and lost the count.

This commit:
* Runs the scan in the admin server after the request returns, one at a
  time, with its status and resume point in Redis.
* Walks emails in id ranges and filters domains in SQL.
* Skips and counts accounts that fail to disable.
* Adds a status route per blocklist, which the panel polls for progress.
* Logs the start, result and failure of each scan with the admin and job id.

Closes #FXA-15088
