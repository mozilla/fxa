Summary
feat: add Glean metrics to the pair2 pairing flows
Description
Because:

* The pair2 screens ship with no metrics, so the pairing funnel is invisible on
  both devices and on the server, and nothing reported whether a QR scan reached
  Firefox, fell back to the app store, or was swallowed by a WebView.
* The two devices are separate sessions with separate flow ids, so their halves
  of one pairing could not be joined.
* Glean's automatic events report window.location.href, so the pairing channel
  key in the URL fragment was being sent to telemetry.

This commit:

* Instruments every action on the 12 Pair2 pages, adds dtm_desktop/dtm_mobile
  view events for the interrupted and success screens, and adds four dtm_mobile
  deeplink events to the supplicant hand-off in DownloadFirefox and PocPairInit,
  with armStoreFallback reporting which inference sent the user to the store.
* Adds dtm_backend.pair_success on /oauth/authorization, detected by a positive
  test for desktop Firefox so an iPad sign-in is not counted as a pairing.
* Captures the pairing fragment at startup and removes it from the URL, keeping
  the channel key out of telemetry, and points the readers that parsed the live
  hash (Pair/Index, App's v=2 bypass, UrlHashData) at the capture instead.
* Adds session.pairing_channel_hash from a SHA-256 of the channel id, resolved
  once at page load so every event in the flow carries the same value.
* Bounds the ping flush before hand-off navigations with a shared helper and
  keeps one failed ping from wedging the submit queue, so telemetry cannot
  strand the user.
