Summary
fix(react): fall back to unhashed l10n path on a missing map entry
Description
## Because

- The settings app fetched `static-asset-manifest.json` at runtime to find the hashed l10n file names.
- A stale copy of that file on the CDN pointed at bundles that no longer exist, and then every locale failed to load.
- The first round of this branch trusted the new map completely. One missing entry left that locale with no strings at all.

## This pull request

- Embeds the l10n static asset map in the settings HTML, in the `fxa-l10n-asset-map` meta tag.
- Removes the runtime fetch of `static-asset-manifest.json`, and with it the stale CDN failure.
- Changes `fetchMessages()` so a missing or non-string map entry falls back to the unhashed `locales/<locale>/<bundle>.ftl` path for that one lookup.
- Keeps the `reportBundleError` call on that path, so the gap is still visible.
- Leaves the guard for an unusable whole map as it was.
- Adjusts one unit test to cover the fallback.
