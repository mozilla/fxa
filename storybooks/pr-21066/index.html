Summary
fix(settings): cap bounce polling at 5 minutes
Description
Because:

- Ten minutes at the 5s interval is 120 requests, but the server allows 100
  emailBounceStatusCheck per IP per 15 minutes and blocks on breach.
- The rule keys on IP, so one signup tab took bounce detection down for
  everyone behind the same address.
- A check left in flight by a previous run could report its bounce against
  whichever email the page had moved on to.

This commit:

- Shortens the cap to 5 minutes, for 60 requests.
- Skips the effect when there is no email to check.
- Ignores a bounce result that arrives after its run was cleaned up.
