Summary
feat(settings): record why a pairing failed on each device
Description
Because:

- timeout_view reported `timeout` for every failure, so a real timeout could not be told from a dropped connection or an error.
- Neither device can tell an expired channel from a closed one, so only a timer of its own can report a timeout.
- The channel hash was only set on supplicant pages, so the two devices' events could not be joined.

This commit:

- Adds a `cause` extra to both timeout_view events, derived from how the pairing socket closed.
- Reports `reason` as `unknown` for any failure that is not a timer expiring or a cancel.
- Times out each waiting page after `qrTimeoutMinutes`, on both devices.
- Captures a Sentry message when a pairing fails, tagged with its cause and state.
- Records the channel id the authority creates, so its events carry the channel hash.

Closes FXA-15085
