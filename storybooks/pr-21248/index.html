Summary
fix(content-server): keep a React route entry for finish account setup
Description
## Because

- `post_verify/finish_account_setup/set_password` was the last Backbone page behind a live subscription email link. It blocks the Backbone removal.
- The React SetPassword page already exists, but its container needs a session. This link carries a JWT instead, so it needs its own container.

## This pull request

- Renders the React SetPassword page at `post_verify/finish_account_setup/set_password`. The path joins the `postVerifyThirdPartyAuthRoutes` group in `react-app/index.js` and gets a route in `components/App/index.tsx`.
- Adds `finish-account-setup-container.tsx`. It validates the email link params, calls `authClient.finishSetup` with the JWT, stores the account with `storeAccountData`, then redirects to mozilla.org.
- Adds a `subscription` password creation reason, an optional `productName`, and a `subscription-set-password` form type, so the button reads "Create password".
- Deletes the Backbone view, its mustache template and its spec. The path stays in the `content-server-routes.js` FRONTEND_ROUTES.
- Keeps a `createReactViewHandler` entry for the path in the Backbone router, so a flag-off environment still routes to React. The flag itself becomes unconditional in #21245.
