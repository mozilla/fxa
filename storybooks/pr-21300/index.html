refactor(content-server): remove Backbone pairing and CAD routes
Description
## Because

- React serves all of the pairing, CAD, and CAD-via-QR routes, so the Backbone versions are dead code.
- The `pairRoutes` flag kept a Backbone fallback path and extra branches in fxa-settings and the functional tests.

## This pull request

- Removes the Backbone `pair/*`, `connect_another_device`, and `post_verify/cad_qr/*` views, templates, mixins, models, and specs from fxa-content-server.
- Sends the Backbone `pair` and `connect_another_device` routes to React. The CAD route passes `showSuccessMessage` and `type` as query params, and the React page now reads `type` from the query.
- Removes the `showReactApp.pairRoutes` and `postVerifyCADViaQRRoutes` flags, folds `get-frontend-pairing` into `getFrontEnd`, and drops the `/oauth?channel_id` Backbone bypass in `add-routes.js`.
- Makes the `/pair` soft navigation in `Signin/utils.ts` unconditional.
- Deletes the Backbone-only pairing functional specs and the `useReact` option in `pairing-helpers.ts`.
- Review round 1: replaces every `hardNavigate('/pair', {}, true)` in fxa-settings with `useNavigateWithQuery()`, so `/pair` keeps the query string without a full reload. This covers `ConnectAnotherDevice`, `InlineRecoveryKeySetup`, `CompleteSignin`, and `SignupConfirmedSync`. The tests check the soft navigation and that `hardNavigate` is not called. The `/pair/authority/scan_qr` hard navigations do not change.
