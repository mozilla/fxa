fix(settings): make email-first submission tests pass in isolation
Description
## Because

- Four tests under `processEmailSubmission` created their Glean spies after the code under test had already run, so the assertions checked a spy that was never in place during submission.
- They still passed in a full-file run. An earlier test had swapped the real method for a mock, and `afterEach(jest.resetAllMocks)` only clears call history, so the late `jest.spyOn` picked up that leftover mock.
- Run on their own, those four failed: "with an existing email", "when called with an email mask", "when called with a firefox.com email", and "when called with an invalid email domain".

## This pull request

- Creates the `submitSuccess` and `submitFail` spies in a `beforeEach` inside the `processEmailSubmission` describe, ahead of any render.
- Reuses those two spies across the tests in that block instead of re-spying mid-test.
- Drops two `// no Glean event emitted with this error type` comments that said the opposite of the assertion under them.
- No assertion was removed or loosened, no test skipped, and no production code touched.
