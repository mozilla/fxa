Summary
fix(settings): destroy the browser session token on sign-out
Description
## Because

- On sign-out, `DropDownAvatarMenu` destroyed only the stored session token. Then it sent `fxaccounts:logout` to Firefox.
- A forced web sign-in can replace the stored token without a page reload. The token that Firefox holds then stays live on the server.

## This pull request

- Adds `getBrowserSessionToken` to `DropDownAvatarMenu/index.tsx`. In Firefox only, it asks the browser for its token with `firefox.requestSignedInUser` (`fxa_status`).
- Destroys that token with `authClient.sessionDestroy` when the uid is the same and the token is different. This runs after `session.destroy()` and before `fxaLogout`.
- Ignores errors from that destroy, so the local sign-out and `fxaLogout` still run.
- Adds unit tests in `DropDownAvatarMenu/index.test.tsx` and a functional test in `fxaStatus.spec.ts`.
- Round 1: the functional test now uses the `syncOAuthBrowserPages` fixture (`oauth_webchannel_v1`). It signs in as the Sync OAuth specs do: `signUpSync`, `gotoSyncSession`, the sign-in code, `clickNotNowPair`. The assertions are the same.
